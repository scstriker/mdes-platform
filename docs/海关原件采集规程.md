# 海关原件采集规程

## 交付单位与查询组合

每个批次对应一个自然月、一个流向、一种分组和一组中国海关 8 位商品编码（HS8）。范围取自《医疗器械HS编码最终版_202601_164项.csv》的“HS海关编码”列，目录版本为 `202601`。币种选美元。首批用清单中的心电图记录仪 `90181100` 跑通以下八次查询。

| 分组 | 进口查询 | 出口查询 | 在官网选中的输出字段 |
| --- | --- | --- | --- |
| 商品 | `import / product` | `export / product` | 商品 |
| 贸易伙伴 | `import / partner` | `export / partner` | 商品、贸易伙伴 |
| 贸易方式 | `import / regime` | `export / regime` | 商品、贸易方式 |
| 注册地 | `import / region` | `export / region` | 商品、收发货人注册地 |

商品组给出该商品的全国金额。其余三组分别解释这笔金额的伙伴、贸易方式和地区构成。按组独立存档和导入。同一笔贸易可以同时出现在四个分组中，计算全国总额只取商品组。注册地使用官网给出的收发货人注册地编码和名称。

## 在海关平台导出

1. 打开海关统计数据在线查询平台，进入“数据查询”。选择进口或出口，币制选“美元”，起始和截止都选同年同月。例如，采集 2026 年 1 月时，两端均选 2026 年 1 月。[海关统计数据在线查询平台](http://stats.customs.gov.cn/)
2. 第一输出字段选“商品”。选择 8 位商品编码，按本批清单粘贴编码，核对平台选中项。其余输出字段按上表设置。伙伴、贸易方式、注册地都用全部成员。四次查询保持月份、流向、币种和商品集合一致。
3. 查看结果，核对已选月份、币种、输出分组。保留官网提供的第一数量、第二数量及各自计量单位。点击页面的“导出数据”，取得该次查询的 CSV。切换流向时重新核对条件。
4. 先保存下载的原始字节，再用只读方式预览表头和明细。遇到官网明确显示无记录的情况，按下一节保存证据。超时、下载中断、返回网页或只查到部分编码时，登记为待补采。
5. 八个组合均取得原件或明确的空结果后，按单码、同月、同流向核对。分别将伙伴、贸易方式和注册地的明细金额加总，与商品组的美元金额比对。记录差额及对应的官网原件，查清缺码、合计行或源端舍入差异后再扩大采集。

试采通过后，按清单顺序切成互不重叠的稳定编码组，保存每组的完整 HS8 列表。每个编码组跑完八个组合。若首次选取的一组超出平台可导出范围，先拆成能完整导出的较小组，再固定这组的范围用于日后重采。采集进度按月份、流向、分组和实际覆盖的编码登记。

## 批次清单与原件

每个批次保存一份 `manifest.json`，与一次官网导出对应。以下是单码有数据的例子。

```json
{
  "dictVersion": "202601",
  "month": "2026-01",
  "flow": "import",
  "currency": "USD",
  "grouping": "partner",
  "hs8": ["90181100"],
  "emptyHs8": []
}
```

`hs8` 列出本次实际选中的全部 8 位编码，以字符串保存。`emptyHs8` 只列官网明确无记录的已选编码，是 `hs8` 的子集。一个编码的某个伙伴或某种贸易方式没有明细，并不表示整个编码为空。

| 官网结果 | 如何留证与交付 |
| --- | --- |
| 导出含明细的 CSV | 保存原文件，在导入请求中作为 `file` 提交。逐项核对返回的 HS8。在同一批内，有金额为 0 的明细仍按已返回记录处理。 |
| 部分选中编码未出现在明细中 | 对缺少的编码按原月份、流向、币种和分组另查。取到明细时重新取得完整批次原件。官网明确无记录时在原批 `emptyHs8` 中列出相应编码，连同 CSV 提交能对应这些编码的 `emptyEvidence` 截图。 |
| 已选编码全部明确无记录 | 保存含查询条件和空结果的 PNG，作为 `emptyEvidence` 提交。官网同时提供表头空 CSV 时，将原文件作为 `file` 一并提交；仅有页面时只提交截图与清单。`hs8` 与 `emptyHs8` 集合相等，导入行数为 0。 |
| 条件未确认、查询报错或下载失败 | 保留失败记录，按相同条件重试。该编码维持待补采状态，月度覆盖统计只计算有原件或有明确空证据的编码。 |

将原始 CSV 或 PNG、七字段清单、原始文件名、采集时间及 SHA-256 一起归档。哈希单独记载，针对文件原始字节计算。Windows 可运行 `Get-FileHash -Algorithm SHA256 -LiteralPath '原始文件.csv'`。按月份、流向、分组、编码批和采集修订分目录保存，以便找回每次导出的文件。已有原件保留编码、字节顺序标记、引号和换行；需要供人阅读时另存副本。

## 表头、修订和重放

适配器按实际表头认列。商品组读取商品代码、名称和美元金额。其他分组在此基础上读取对应的伙伴、贸易方式或注册地代码与名称。例如旧脚本使用“商品代码”“贸易伙伴编码”“注册地编码”和“美元”。官网导出可能换用“商品编码”等标题。实际标题与字段的对应关系随原件留存。月份和流向由查询清单提供，若文件内也有月份，则和清单核对。中文编码按原件识别，已知旧导出会用 GBK，另有 UTF-8 文件。预览时用 CSV 解析器处理引号内的逗号、换行及带千位分隔符的金额。

对照旧脚本时，`iEType=1` 表示进口，`0` 表示出口，`currencyType=usd` 表示美元。商品、伙伴、方式和注册地对应脚本中的 `CODE_TS`、`ORIGIN_COUNTRY`、`TRADE_MODE`、`TRADE_CO_PORT`。旧脚本的汇总模式会重写表头并合并多次导出；新的采集适配器须在解码和合并前保存每一次官方响应的原始字节。按上述分组保留原件，合并文件可另外用于人工查看。

数量与对应法定单位成对保留。第二数量、第二单位在原件中留空时保留缺失值。按同一商品和单位核对数量，行业汇总使用美元金额。原件中的全国合计、分组合计只用于对账，明细与合计分开识别。

官网修订时，用相同目录版本、月份、流向、币种、分组和同一组 HS8 再查一次。将新原件、新清单和新哈希作为下一修订归档，记录它替换的批次、美元金额差异及消失的行。导入后查回新批次，确认更正金额已生效、已撤销行已移除。再次提交相同原件应返回原批次。历史原件重放也应返回当时的批次，当前发布结果继续采用新修订。
